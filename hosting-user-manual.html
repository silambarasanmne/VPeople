Chapter 02

Register a Domain on BigRock

How to purchase and manage your domain name at bigrock.in

1

Go to BigRock Website

Open your browser and navigate to:

https://www.bigrock.in
2

Search for Your Domain

In the search bar on the homepage:

  1. Type your desired domain name (e.g., yourdomain.com)
  2. Click "Search"
  3. BigRock will show if the domain is available
  4. Select the domain extension you want (.com, .in, .org, etc.)
3

Purchase the Domain

  1. Click "Add to Cart" next to your chosen domain
  2. Choose registration period (1 year, 2 years, etc.)
  3. Review the cart and click "Proceed to Checkout"
  4. Create a BigRock account (or log in if you already have one)
  5. Complete payment via Credit Card / Debit Card / UPI / Net Banking
💡
Tip: Skip any additional add-ons (hosting, email, etc.) offered during checkout — you already have hosting from MrHost.
4

Access Your Domain Management

After purchase, manage your domain:

https://myorders.bigrock.in

Log in with your BigRock email and password. You will see your domain listed under "My Orders".

Chapter 04

Connect Domain to Hosting (DNS Setup)

Point your BigRock domain to MrHost server using nameservers

⚠️
Important: This is the most critical step. Without this, your domain won't connect to your hosting server. You have 2 options — choose one.

Option A: Change Nameservers (Recommended)

This hands over full DNS control to your hosting provider.

1

Log in to BigRock

Go to https://myorders.bigrock.in and log in.

2

Open Domain Settings

Click on your domain name to open the management page.

My Orders → yourdomain.com → Name Servers & DNS
3

Update Nameservers

Replace the existing BigRock nameservers with MrHost nameservers:

Old Nameserver (Remove) New Nameserver (Enter)
dns1.bigrock.in ns1.server.ayiarak.in
dns2.bigrock.in ns2.server.ayiarak.in
dns3.bigrock.in (Remove — leave blank)
dns4.bigrock.in (Remove — leave blank)

Click "Update" / "Save" to apply changes.

Option B: Add A Records (Faster Alternative)

Keep BigRock's nameservers but point the domain to your server IP via A records.

1

Go to DNS Records in BigRock

My Orders → yourdomain.com → DNS Management → Manage DNS Records
2

Add A Records

Click "+ Add A Record" and add these two records:

Host Points To (IP Address) TTL
@ YOUR_SERVER_IP 14400
www YOUR_SERVER_IP 14400
💡
Tip: Replace YOUR_SERVER_IP with the actual server IP from your Plesk panel (e.g., 94.136.187.4).
⏳
DNS Propagation Time:
• Option A (Nameservers): Takes 24–72 hours for full global propagation
• Option B (A Records): Usually propagates within minutes to a few hours

Check propagation status at: https://www.whatsmydns.net
Chapter 05

Add Domain in Plesk Panel

Configure your domain inside the Plesk hosting control panel

1

Navigate to Websites & Domains

In the Plesk dashboard, go to:

Plesk Dashboard → Websites & Domains
2

Add Your Domain

If your hosting plan supports multiple domains:

  1. Click "Add Domain"
  2. Enter your domain name (e.g., yourdomain.com)
  3. Set hosting type to "Website hosting"
  4. Set document root (default: httpdocs)
  5. Click "OK"
⚠️
Single Domain Plan? If you don't see "Add Domain" option, your plan only supports one domain. Instead:
  1. Go to "Hosting Settings" of the existing domain
  2. Change the domain name to your new domain
  3. Or add it as a "Domain Alias" under Hosting & DNS
3

Configure Hosting Settings

Websites & Domains → yourdomain.com → Hosting Settings

Verify these settings:

Setting Recommended Value
Document Root httpdocs (or your project subfolder path)
SSL/TLS Support ✅ Enabled
Permanent redirect to HTTPS ✅ Enabled (after SSL setup)
PHP Version Latest stable (8.x recommended)
Chapter 06

Deploy Website Files via Git

Push your code from GitHub directly to the live server

Part A: Push Code to GitHub (Local Computer)

1

Initialize Git Repository

Open terminal/command prompt in your project folder and run:

# Initialize a new git repository
git init

# Add the remote GitHub repository
git remote add origin https://github.com/YOUR_USERNAME/YOUR_REPO.git

# Stage all files
git add .

# Create initial commit
git commit -m "Initial commit"

# Rename branch to main
git branch -M main

# Push to GitHub
git push -u origin main

Part B: Connect Git in Plesk (Server)

2

Open Git in Plesk

Websites & Domains → yourdomain.com → Dev Tools → Git

Click on "Git" under the Dev Tools section.

3

Add Repository

  1. Click "Add Repository" or "Clone Repository"
  2. Fill in the following details:
Field Value
Remote Git Repository URL https://github.com/YOUR_USERNAME/YOUR_REPO.git
Deploy to httpdocs (your document root)
Branch main
Auto-deploy ✅ Enable for automatic updates

Click "OK" to clone the repository.

4

Deploy the Code

  1. After cloning is complete, click "Pull now" to get the latest code
  2. Click "Deploy now" to deploy files to the document root
  3. Verify files in File Manager → httpdocs
💡
Auto-deploy: With auto-deploy enabled, every time you git push from your local computer, Plesk will automatically pull and deploy the latest changes!
5

Verify Document Root

Make sure the document root in Hosting Settings matches where your index.html file is located.

⚠️
Common Issue: If the deployment creates a subfolder (e.g., httpdocs/ProjectName/ProjectName), update the document root in Hosting Settings to match this path.

Part C: Future Updates

When you make changes to your website locally:

# Stage changed files
git add .

# Commit with a descriptive message
git commit -m "Updated homepage design"

# Push to GitHub
git push origin main

Then in Plesk → Git → click "Pull now" → "Deploy now"

Chapter 07

Install SSL Certificate (HTTPS)

Secure your website with a free Let's Encrypt SSL certificate

ℹ️
Prerequisite: DNS must be fully propagated (domain must resolve to your server IP) before SSL can be issued. Check at https://www.whatsmydns.net
1

Navigate to SSL/TLS Certificates

Websites & Domains → yourdomain.com → Security → SSL/TLS Certificates
2

Install Let's Encrypt Certificate

  1. Click "Install" next to Let's Encrypt
  2. Select these options:
Option Action
✅ Secure the domain name yourdomain.com — Check this
✅ Include "www" subdomain www.yourdomain.com — Check this
❌ Secure wildcard domain *.yourdomain.com — Uncheck
❌ Secure webmail webmail.yourdomain.com — Uncheck (unless needed)
❌ Secure mail mail.yourdomain.com — Uncheck (unless needed)
3

Choose Validation Method

Method When to Use
DNS (dns-01) ✅ Recommended — Use when your nameservers point to the hosting server
HTTP (http-01) Use when domain already resolves to your server via A records
4

Get the Certificate

  1. Click "Get it free"
  2. Wait for Let's Encrypt to verify and issue the certificate
  3. Once done, you'll see "Secured" next to your domain
🔄
Auto-Renewal: Let's Encrypt certificates are valid for 90 days but Plesk automatically renews them 30 days before expiration. No manual action needed!

✅ Expected Result After SSL Setup

  • ✓
    yourdomain.com — Secured
  • ✓
    www.yourdomain.com — Secured
Chapter 08

Set Up HTTP to HTTPS Redirect

Force all website traffic through secure HTTPS connection

After installing SSL, visitors who type http://yourdomain.com still see "Not Secure". You need to redirect HTTP → HTTPS.

Method 1: Via Plesk Hosting Settings (Easiest)

1

Enable HTTPS Redirect

Websites & Domains → yourdomain.com → Hosting Settings

Enable these checkboxes:

  • ✓
    SSL/TLS support — Enables HTTPS
  • ✓
    Permanent SEO-safe 301 redirect from HTTP to HTTPS

Click "OK" to save.

Method 2: Via .htaccess File (Manual)

If Method 1 is not available, create a .htaccess file in your document root:

1

Create .htaccess File

Create a file named .htaccess in your website's root folder (where index.html is located) with this content:

RewriteEngine On
RewriteCond %{HTTPS} off
RewriteRule ^(.*)$ https://%{HTTP_HOST}%{REQUEST_URI} [L,R=301]
💡
Git Method: Add this file to your project, commit and push to GitHub, then deploy via Plesk Git.

Verify & Test Your Website

Final checks to ensure everything is working correctly

Verification Checklist

✓ Check How to Verify
☐ DNS Resolution Visit https://www.whatsmydns.net and search for your domain
☐ Website Loads Open https://yourdomain.com in a browser
☐ HTTPS Works Look for the 🔒 lock icon in the address bar
☐ WWW Works Visit https://www.yourdomain.com — should also load
☐ HTTP Redirects Visit http://yourdomain.com — should redirect to HTTPS
☐ Mobile Responsive Open on a mobile phone or use Chrome DevTools (F12 → Mobile view)
☐ All Pages Load Click through all links and pages on the site
☐ No Mixed Content Open Chrome DevTools (F12) → Console → Check for warnings
🔍
Test in Incognito Mode: Always test your site in an incognito/private browser window to avoid cache issues. Press Ctrl + Shift + N (Chrome) or Ctrl + Shift + P (Firefox).
🧹
If site shows "Not Secure" in regular browser but works in Incognito:
Clear your browser cache: Ctrl + Shift + Delete → Select "All time" → Clear "Cached images and files" → Reload.

Troubleshooting & FAQ

Common issues and their solutions

?

"Domain is not resolvable" in Plesk

Cause: DNS hasn't propagated yet after changing nameservers.

Solution: Wait 24–72 hours. Check status at whatsmydns.net. You can still deploy files during this time.

?

SSL Certificate Installation Fails

Cause: DNS hasn't propagated to the server IP.

Solution: Wait for DNS propagation to complete, then try installing SSL again. Try the DNS (dns-01) validation method instead of HTTP.

?

Website Shows Plesk Default Page

Cause: Document root is pointing to the wrong folder.

Solution: Go to Hosting Settings and verify the document root points to the folder containing your index.html file. Check File Manager to confirm file locations.

?

Browser Shows "Not Secure" Warning

Cause 1: HTTP to HTTPS redirect is not enabled.

Solution: Enable "Permanent 301 redirect to HTTPS" in Hosting Settings or add .htaccess redirect.

Cause 2: Browser cache.

Solution: Clear cache (Ctrl + Shift + Delete) or test in Incognito mode.

?

Git Deployment Creates Nested Folders

Cause: Repository name creates extra subdirectory during deployment.

Solution: Update the document root in Hosting Settings to match the actual file path. For example: httpdocs/ProjectName/ProjectName

?

"Add Domain" Option Not Available in Plesk

Cause: Your hosting plan only supports a single domain.

Solution: Either change the primary domain name in Hosting Settings, or add your domain as a Domain Alias.

?

PHP Files Not Working / Showing Code

Cause: PHP is not enabled or wrong version selected.

Solution: Go to Websites & Domains → PHP → Enable PHP and select version 8.x.
